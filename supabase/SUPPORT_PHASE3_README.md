# المرحلة الثالثة — دور موظف الدعم الفني

## ما تتضمنه المرحلة

- عضوية موظف الدعم محفوظة في `support_agents` منفصلة عن `profiles.role`.
- المالك وحده يستطيع إضافة موظف، تعطيله أو إعادة تفعيله، ضبط إشعاراته، أو إزالة عضويته.
- صفحة إدارة الموظفين تعرض البريد والحالة وأعداد التذاكر المسندة والمفتوحة والمغلقة.
- صلاحيات الموظف على التذاكر والرسائل والمرفقات محكومة في قاعدة البيانات بسياسات RLS ودوال الصلاحيات، وليس بإخفاء عناصر الواجهة.
- إزالة العضوية لا تحذف حساب المستخدم أو التذاكر؛ التذاكر السابقة تبقى محفوظة ويمكن للمالك إعادة إسنادها.

## النشر

بعد تحديث ملفات المشروع في GitHub، أعد نشر Edge Function من مجلد المشروع:

```powershell
npx.cmd supabase functions deploy admin-users
```

لا تُعد تشغيل ملفات SQL الخاصة بالمرحلة الثانية إذا كانت قد طُبقت ونجح اختبارها. استخدم `SUPPORT_PHASE2_README.md` فقط إذا كنت تجهز قاعدة البيانات من البداية.

## التحقق

- اختبار الصلاحيات الذي شغّله مالك المشروع أعاد `SUPPORT_TESTS_RESULT: 30/30 passed` بعد إصلاح سياسات المرحلة الثانية.
- صفحة إدارة موظفي الدعم ظهرت في لوحة المالك، وتمت إضافة موظف وتغيير حالته في الاختبار اليدوي الذي أرسله المالك.
- يلزم بعد نشر هذه النسخة التحقق من إزالة العضوية، ثم تسجيل الدخول بحساب موظف الدعم والتأكد من منعه من لوحة إدارة الموقع. لا أملك بيانات دخول لحسابات المشروع لإجراء هذين الاختبارين من هنا.
