# المرحلة الرابعة — واجهة العميل وإنشاء التذاكر

## الواجهة

- رابط «الدعم الفني» يظهر في تنقل الموقع ويأخذ العميل إلى `index.html#support`.
- لا يظهر نموذج الدعم إلا بعد تسجيل الدخول بحساب موقع صالح.
- الفئات والفئات الفرعية تُحمّل من قاعدة البيانات؛ اختيار الفئة الرئيسية يحدّث قائمة الفئات الفرعية.
- إنشاء التذكرة وأول رسالة يتمان معًا عبر `support_create_ticket`، مع مفتاح طلب يمنع تكرار إنشاء التذكرة عند إعادة المحاولة.
- يعرض القسم آخر 10 تذاكر للعميل الحالي فقط.
- المرفقات: JPG/JPEG وPNG وPDF، 5 ملفات كحد أقصى، و5MB لكل ملف.
- الواجهة تدعم العربية RTL والإنجليزية LTR وتتبع تفضيل اللغة والمظهر بالموقع.

## تشغيل حماية المرفقات قبل النشر

بعد نشر ملفات الواجهة إلى GitHub، وقبل تفعيل رفع المرفقات على الموقع:

1. افتح Supabase → SQL Editor.
2. شغّل `migration_support_4_customer_storage.sql` مرة واحدة.
3. تأكد من ظهور Success.
4. حدّث الموقع من GitHub Pages.

هذا التحديث يزيل سياسات Storage القديمة التي قد تسمح بقراءة مرفقات الملاحظات الداخلية أو رفع ملفات إلى تذاكر مستخدمين آخرين.

## ملاحظة رقم الطلب

المشروع الحالي لا يحتوي على جدول طلبات. لذلك الحقل اختياري ويحفظ قيمة مرجعية فقط؛ لا توجد آلية حقيقية لاختيار طلبات المستخدم أو التحقق من ملكيته حتى يُضاف جدول طلبات موثوق.

## اختبار المرحلة

يلزم من حساب عميل حقيقي:

1. فتح `index.html#support` أثناء تسجيل الخروج والتأكد أن النموذج محجوب ويطلب تسجيل الدخول.
2. تسجيل الدخول ثم التأكد من تحميل الفئات وسجل تذاكر الحساب.
3. إرسال تذكرة بلا مرفق، والتحقق من رقمها وظهورها في سجل العميل.
4. إرسال تذكرة بمرفق مسموح، والتحقق من وجود الملف وسجل المرفق في Supabase.
5. المحاولة بملف أكبر من 5MB أو نوع غير مسموح، والتأكد من رفضه قبل الرفع.
6. تشغيل `support_tests.sql` بعد الاختبارات عند الحاجة؛ بيانات اختبار SQL تتراجع تلقائيًا.

واجهة المحادثة والردود ومتابعة الرسائل مرحلة منفصلة لاحقة.
